実際の描画系（GLB、BVH、草シェーダ、水面、InstancedMesh）を通して、真値を台本どおりに動かしたときに各痕跡が出るかを確かめた。

## 3. 目視確認（内蔵ブラウザのスクリーンショット）

| 確認内容 | 結果 / 対処 |
|---|---|
| Blender の森が Three.js に表示される | OK |
| 泥の上の蹄跡 | **当初は見えなかった** → 原因は 2 つ: ①窪みが地面より 12 mm 下に潜り、深度テストで隠れていた ②bmesh の sRGB を二重変換して真っ黒だった。持ち上げ・sRGB 修正・面の向き修正・2 倍拡大で、進行方向の読める蹄跡列になった |
| 草の倒れ跡 | **当初は薄すぎた** → 体の押し幅・強さを上げ、倒れた草を淡い枯れ色にして、斜めの踏み分け道として読めるようにした |
| 水たまりと波紋 | **当初は水面がほとんど見えなかった**（深さ 2 cm で泥に覆われていた）→ Blender で窪みと土手を彫り直した。波紋が強すぎて白く飽和したので振幅を 0.22 倍にし、着地点を中心とした同心円が読めるようになった |

## 4. 痕跡だけで推理できるか（`node tests/inference.analysis.mjs`）

真値を見ずに足跡イベントだけを見る素朴な推定器を、10 分間 × シード 8 本で 5 秒ごとに評価した。

| 推定器 | 1.6 m 以内に当たる割合 |
|---|---|
| 最新の足跡（全種類が見えていると仮定） | 100% |
| 足跡列からの外挿 | 100% |
| **泥の足跡だけが見える**（遠くから確実に読める痕跡だけ） | **42〜61%** |
| （参考）動物が静止している時間の割合 | 30〜36% |

読み取り:
- 情報としては、痕跡だけで位置は決まる（問題として成り立っている）。難しさはすべて「見つけられるか・新しさを判断できるか」という知覚の側にある。
- 泥の足跡だけで 4〜6 割当たるのは、水を飲みに来る行動のせいで動物が泥の周りに集まりやすいため。**泥場で待つのが強すぎる戦略になりうる** → 改善提案 1。

## 5. 未実施・制限（正直な申告）

- **人の手でのポインターロック試遊はしていない。** 自動テストからはマウスでの視点操作を再現できないため、WASD・しゃがみ・右クリックでのスキャンは、コードと自動フック（`TRACE.scanAt` など）での確認にとどまる。最初の人手プレイで操作感を確認してほしい。
- 立体音響は鳴らすところまでは実装したが、聴いて方向が分かるかは確かめていない（自動テストでは音を聴けない）。
- fps は Iris Xe・1024×768 の 1 環境だけで測った。

## 6. 改善提案（Phase 6）

1. **泥場キャンプ対策**: 喉の渇きの周期を延ばす、水場を増やす、または水を飲んだあとは泥を避ける性質を付ける。泥を「見落とせない痕跡」から「ときどき出る決定的な痕跡」にする。
2. **草の上の淡い足跡が草に埋もれる**: しゃがむと足元 3 m の痕跡のコントラストが上がる「観察姿勢」を入れる（しゃがみ＝静か＝近づける、と噛み合う）。
3. **プレイヤー自身の痕跡との混同**: プレイヤーが割った枝や立てた波紋も同じ見た目になる。靴跡を残すか、自分の痕跡は少し違う色にする。
4. **性能**: 草を 8 m 四方程度のチャンクに分けて視錐台で間引く。水たまりを増やすなら波紋を `GPUComputationRenderer` へ移す。
5. **スキャン失敗時の情報量**: 「近い / 遠い」の 2 段階だけなので、外したスキャン地点からの方角のヒント（音の方向のように）を検討する。
